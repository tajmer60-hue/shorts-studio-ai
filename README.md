# Shorts Studio AI — API-версия в разработке

Версия 0.3.1.dev1. Основной экран заменён: видео → одна кнопка обработки → готовые истории → просмотр и сохранение. Ручной нарезчик больше не основной экран.

## Запуск на этом компьютере

Открыть `D:\ShortsStudioAI\project\start.bat`. Используется уже установленное окружение и модель речи на D:. Старые ZIP-сборки не обновляются автоматически.

По последнему решению пользователя API выключен: «Пока только подготовить, без платных запросов». Кнопка «Подготовить серию без расходов» распознаёт весь исходник локально, извлекает обзорные кадры и сохраняет пакет. Она НЕ создаёт фальшивые AI-результаты. Для облачного испытания позднее нужны ключ, бюджет и явное включение отправки в интерфейсе. Не присылайте ключ в чат.

## Реализованный путь

- Локальное распознавание всей серии; окна по 5 минут с перекрытием 15 с, по 10 кадров на окно.
- Провайдер выбирается в интерфейсе: `free` (по умолчанию), `auto`, Gemini API напрямую, Groq или OpenRouter.
- **Бесплатный путь — основной**: `nvidia/nemotron-3.5-super-vl:free` (контекст 1 000 000, текст+картинки+видео) и `nvidia/nemotron-3.5-content-safety:free` для цензуры. Цена $0; лимит считается запросами в сутки, остаток читается у провайдера через `GET /api/v1/key` до отправки. Серия 55 минут — это ~14 запросов, то есть около 3 серий в день бесплатно.
- Бесплатные эндпоинты требуют явного разрешения на обработку данных: без отдельной галочки маршрут уходит на платные модели с запретом передачи (`deny`). Выбор делает пользователь, а не код. Основной — Gemini, потому что только он принимает изображения; Groq помечен как текстовый и автоматически пропускается на запросах с кадрами. Сравнение пяти сервисов и обоснование выбора — в [AI_PROVIDERS.md](AI_PROVIDERS.md).
- Отбор событий каждого окна, затем общий редакторский проход. Отправляются реплики и уменьшенные изображения, а не файл фильма. Каждый запрос ограничен; нет автоматических повторов после ошибок.
- Контроль расходов: резерв списывается до запроса, журнал в SQLite, кэш ответов по отпечатку входа, оценка стоимости до отправки, остаток квоты читается из ответа провайдера, а не из зашитой константы. Неподтверждённый тариф показывается как «цена неизвестна», а не как выдуманное число.
- AI Hook Director: хук 0–100 по семи факторам берётся только из начала ролика (без обмана зрителя), слабое начало помечается на проверку; план звуковых акцентов с тишиной как полноправным вариантом.
- Music Director с лицензионной дисциплиной: треки из подборок заказчика — стилевые ориентиры с `NOT_CLEARED`, рендер их не использует; без лицензированного файла ролик идёт с оригинальной дорожкой. Beat Sync: BPM/биты/дропы локально, склейки тянутся к битам только без ущерба сюжету и словам, музыка давится под реплики и ограничивается лимитером.
- Профили каналов: Serial Story, Phonk Viral Edit, Cinematic Drama и свои; профиль управляет режимом, длительностью, интенсивностью, жанрами, субтитрами, цензурой и экспортом.
- Детектор заставок, рекапа и финальных титров: мульти-сигнальный (позиция, чёрные кадры, отсутствие речи, маркеры); субтитры диалога не могут быть приняты за титры, чёрный кадр в середине эпизода не удаляется автоматически. Авто-исключаемые регионы вычищаются из планирования и из кандидатов.
- Два разных режима монтажа. **Serial Cutter** — хронологические связные Part 1..N: вопрос остаётся с ответом, часть по возможности закрывается на напряжении, паузы сокращаются только там, где не затронуто ни одно распознанное слово. **Viral Moments** — независимые самодостаточные пики: кандидат обязан иметь сигнал интенсивности (напряжение реплик, темп выше медианы, смены плана), поэтому «small talk» не проходит; балл помечен как эвристика, а не прогноз просмотров. Оба режима работают без сети и без денег; с разрешением на облако получают режим-зависимые промпты.
- Без разрешения на облако приложение всё равно монтирует ролики локально (уровень Lite из Issue #2): режим + Smart Reframe + цензура по одобренным интервалам, с честной пометкой, что это эвристика, а не вердикт нейросети.
- Smart Reframe: вертикальный кадр следует за субъектом с ограниченной скоростью панорамы и зума; склейка между говорящими читается как движение камеры. Локально, без сети. Если субъект не помещается в честное окно 9:16 — размытый фон вместо чёрных полос. Проверено реальным FFmpeg: объект у левого края в режиме сопровождения занимает >5% кадра против <3% в режиме «вписать с фоном».
- Точечная цензура речи: детекция мата по корням и таймкодам ASR, редактируемый словарь со списком ложных срабатываний, список спорных слов в интерфейсе. Глушатся только отмеченные пользователем интервалы; неуверенно распознанное слово нельзя заглушить одной галочкой.
- Проверка таймкодов, целых слов, порядка и отсутствия повторных исходных кадров. Количество не добивается слабыми сценами до квоты.
- Исполнение нескольких исходных сегментов в одном ролике, короткие fades аудио, 720×1280 с размытым фоном, заголовок и встроенные субтитры.
- Просмотр внутри приложения, перемотка, сохранение точных байтов просмотренного MP4 + SRT + JSON плана. Результаты восстанавливаются после открытия.

## Что реально проверено

Референс пользователя совпадает с references/example.mp4 по SHA-256. Подготовка всего референса через новый GUI прошла без сети. Технический монтаж из трёх вручную заданных диапазонов получился 26.166667 с, 720×1280, звук; декодирование FFmpeg, реальные кадры плеера, сохранение и повторное открытие проверены. Это НЕ доказательство качества AI-отбора.

Дополнительно подготовлена целая серия 61 мин 37 с (778 MB): 13 окон, 130 кадров, 2692 распознанных слова, 676 фраз. Это проверка подготовки, не качества автоматического отбора.

Живой OpenRouter-запрос не выполнялся: пользователь запретил расходы. До проверки с реальным API не считать автоматический отбор принятым. Ответы API в unit-тестах имитируются только для проверки контракта/бюджета/безопасности, а не качества монтажа.

Локально в Linux-песочнице пройдено **272 теста, 2 опциональных ASR пропущены**. Бенчмарк на реальном бесплатном ключе подтвердил основного провайдера измерением: `nemotron-3.5-super-vl:free` поймал 3 из 3 зашитых моментов с нулём мусора и нулём разрезанных слов; 4 из 5 прочих бесплатных эндпоинтов отказали (404/403/429), поэтому цепочка резерва обязательна. Из них три — реальный FFmpeg, а не имитация: на видео с непрерывным тоном проверено, что одобренное слово глушится именно в выходном времени после склейки двух сегментов (2.18–2.62 с исходника → 1.18–1.62 с результата), что остальной звук сохраняется, что без одобрения тишины нет вовсе и что интервал, пересекающий границу склейки, вызывает ошибку вместо половинчатого глушения.

`benchmark.py` готов сравнить кандидатов на одном пакете по объективным метрикам (разрезанные слова, повторы кадров, выход за окно, покрытие, порядок частей, цена), но **на реальном видео он ещё не прогнан**. Реальных запросов к API не выполнялось: все сетевые тесты работают на внедряемом транспорте и доказывают контракт и контроль расходов, а не качество ответов модели.

Сопровождение кадра работает на локальной оценке значимости, а не на детекторе лиц (OpenCV 5 не поставляет каскады Хаара, и имитировать их мы не стали): результат помечен низкой уверенностью и требует просмотра. Обнаружение наготы и крови на реальном видео, музыкальный монтаж и два разных режима пока не готовы. Два режима (Serial Cutter / Viral Moments) пока используют один промпт. Пропуск промежуточного действия возможен из-за редких кадров. Нет измеренной сюжетной связности, слуховой приёмки стыков и испытания полного эпизода >5 GB. ASR ошибается; встроенные исходные надписи и поля автоматически не удаляются, поэтому на референсе видны исходные и новые субтитры.
