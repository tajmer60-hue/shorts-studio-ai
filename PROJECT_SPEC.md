# Shorts Studio AI — масштабная переработка после тестирования первой версии

> **Статус: пользовательское замечание / техническое задание для Codex.**
>
> **Главная проблема:** сейчас программа фактически является ручным FFmpeg-нарезчиком: выбираешь начало, продолжительность и способ кадрирования. Пользователь проверил её на первой серии «Игры престолов» и НЕ получил обещанного интеллектуального монтажа. Нужна полноценная, качественная и устойчивая локальная монтажная студия, а не косметическое исправление текущего интерфейса.
>
> **Цель результата:** загрузить доступный пользователю на законных основаниях фильм/серию, автоматически получить несколько содержательных вертикальных роликов, просмотреть **предложения AI с пояснениями**, подтвердить или исправить монтаж, выполнить проверку цензуры и экспортировать готовые файлы. Референс пользовательского стиля — ранее предоставленный короткий ролик «Ходаков жёстко отомстил Вакутагину за жадность!». Его следует анализировать **локально**, а не коммитить в GitHub.

## 1. Известные дефекты текущей версии — воспроизвести и зафиксировать

- [ ] Вместо отбора лучших сцен приложение требует вручную указать **откуда начать резать** и **сколько секунд**. Устранить это как обязательный пользовательский шаг: автоанализ становится основным сценарием, ручной выбор остаётся опцией.
- [ ] Режим «вписать в 9:16» добавляет большие **чёрные полосы сверху/снизу**, выглядящие как неправильный Shorts. Не использовать его по умолчанию.
- [ ] Режим «обрезать по центру» срезает левые/правые части исходника и **всегда держит неподвижный центр**, вследствие чего могут пропадать лица, действия и значимые объекты.
- [ ] **Нет плавного сопровождения главных объектов**: при смене говорящего, движении персонажа и сцен камера не адаптируется.
- [ ] **Нет монтажа как такового**: нет интеллектуального удаления затянутых пауз, слабых моментов, повторов, несущественных переходов; нет сохранения причинно-следственной связности.
- [ ] Нет интеллектуального пропуска заставки, recap/«ранее в сериале», финальных титров, логотипов и технических чёрных кадров.
- [ ] Нет встроенных субтитров, заглушения мата, выделенного блюра наготы/крови/расчленения, объяснения отбора, музыкального монтажа.
- [ ] Результат **не должен восприниматься как случайный отрезок серии**. С одной серии иногда можно получить несколько сильных Shorts, но количество должно зависеть от качества, а не от заданной квоты.

**Обязательное начало для Codex:** проверить фактический код текущей версии, воспроизвести дефекты на коротких законно доступных тестовых фрагментах, составить матрицу «есть / нет / частично», НЕ объявлять функции готовыми без испытаний.

## 2. Два основных режима — разные алгоритмы

### Режим A: Serial Cutter (сюжетная серийная нарезка)

- Автоматически выделять сюжетные блоки и события с **привязкой к исходным временным меткам**.
- Удалять длинные неинформативные паузы, затянутые проходы, повторы, пустые переходы; оставлять реакции и драматические паузы, если они необходимы.
- Сохранять причинно-следственные связи, порядок ключевых событий, персонажей и реплик. Не склеивать ответы с неправильными вопросами и не создавать ложный смысл.
- Предлагать несколько частей (Part 1, Part 2...) с логичным началом, завершением и возможным напряжением в конце, без обрыва слов.
- Позволять пользователю определить целевой диапазон продолжительности, а не только фиксированную длину.
- Показывать **план нарезки/таймлайн до рендера**.

### Режим B: Viral Moments / Music Edit (главный приоритет по стилю)

- Находить **эмоциональные пики, конфликт, поворот сюжета, угрозу, юмор, реакцию, действие, неожиданную развязку**, сцены, понятные без длительной предыстории.
- Оценивать кандидатов по совокупности признаков: понятность, напряжённость, динамика, визуальная выразительность, наличие ясной кульминации, пригодность для самостоятельного Shorts.
- Поддерживать монтаж под **музыку с правами на использование**: определение битов, ритмичные склейки, управление громкостью диалога и музыки, кульминация/последний кадр. Не использовать чужую музыку без лицензии.
- Не нарушать хронологию в режиме, где она важна; если предлагается нелинейный edit, явно маркировать его и давать пользователю подтверждение.
- Собирать стиль на основании локальных видеореференсов: средняя/медианная длительность плана, темп, паузы, расположение субтитров, громкость, тип переходов, структура хука/кульминации/финала. Не обещать точное копирование чужой работы.
- Предлагать **много кандидатов** с ранжированием, но рендерить только подтверждённые (или включать отдельный безопасный автоэкспорт).

## 3. Интеллектуальное редактирование речи и звука

- [ ] Детекция речи/тишины (VAD), покадровая звуковая шкала, при наличии модели — ASR с точными временными метками слов и выравниванием.
- [ ] Удаление «ээ», запинок, неоправданных пауз и повторов **только если смысл и естественность сохраняются**.
- [ ] Минимальные границы склеек, короткие audio-fades/crossfades для устранения щелчков; по необходимости J/L-cuts, сохранение атмосферных звуков.
- [ ] Различать тишину без содержания и осмысленную драматическую паузу (настройка агрессивности: мягко / нормально / быстро).
- [ ] Сохранять синхронность аудио и видео после каждого выреза; запрет обрыва слогов и фраз; предпросмотр исправленных участков.
- [ ] Создание субтитров с таймкодами, автоматическое разбиение по читаемым смысловым фразам, оформление под 9:16 (без обрезания интерфейсом Shorts), экспорт .srt/.ass + прожиг по желанию.
- [ ] Отдельно обрабатывать звук оригинала и музыкальную подложку; нормализация без клиппинга.

## 4. Умный формат 9:16 — устранить чёрные полосы и мёртвый центр

Нужны 3 явных режима, основной по умолчанию — **Smart Reframe**:

1. **Smart Reframe**: обнаружение говорящих, лиц и важных объектов; отслеживание между кадрами; поиск оптимального окна 9:16; плавные панорамы и удержание выбранного объекта; смена фокуса при смене говорящего/действия; предельная скорость перемещения камеры во избежание «дёрганья».
2. **Background Fill**: когда обрезка теряет критически важную информацию, сохранить центральное изображение полностью и заполнить оставшееся пространство **размытой увеличенной копией исходного кадра** (или выбранным фоном), НЕ чёрным цветом.
3. **Manual Keyframes**: пользователь меняет точку фокуса в ключевых кадрах, остальные положения интерполируются.

Дополнительно:
- Поддерживать одну/две фигуры в кадре и fallback на общий план там, где один кроп невозможен.
- Управлять безопасными зонами под субтитры и UI YouTube Shorts.
- Не перепрыгивать резко между противоположными краями при поиске лица.
- При уверенности детектора ниже порога помечать участок для проверки.
- Предварительный просмотр с наложением **источника и предлагаемого кропа**, возможность корректировки до экспорта.
- Сохранять пропорции без растяжения и не ухудшать разрешение без необходимости.

## 5. Исключение заставок, титров и мусорных фрагментов

Детектор с несколькими сигналами, а не одним правилом:
- заставка, recurring intro, логотипы/обложки, recap, ending credits, чёрные кадры;
- особенности музыки/титров, повторяемые последовательности, смены сцен, OCR надписей, информация о репликах;
- учитывать, что **субтитры с диалогом не являются автоматически титрами** — нельзя вырезать их на основании наличия текста;
- режим проверки «Пропустить автоматически / Предложить / Оставить»;
- на таймлайне сохранять причины исключения и исходные timecodes.

## 6. Smart Censor: речь, нагота, кровь и жестокие сцены

**Приоритет — точечная цензура, а не размытие всего экрана.**

- [ ] Ненормативная лексика: находить по речи с временными метками слов; короткий mute/bleep/замена звуковой дорожки строго в интервале слова; редактируемый словарь и ручная корректировка.
- [ ] Нагота/сексуальные сцены: определять рискованные области, **маскировать только необходимые зоны**; трекинг маски между кадрами с запасом по краям; при низкой уверенности — предупреждение и ручной просмотр.
- [ ] Кровь/расчленение/графическое насилие: локальное маскирование крови, ран/отделённых частей тела и других значимых деталей; при возможности — исключение полностью неважного для сюжета эпизода.
- [ ] Если сцена несущественна и нет важного диалога — предлагать **вырезать её целиком**.
- [ ] Если важный диалог есть — сохранять аудио/смысл и маскировать области либо переключать на нейтральный видеоплан.
- [ ] Сцена, которую детектор не распознал уверенно, **НЕ считается безопасной**: проверка человеком перед финальным экспортом.
- [ ] Предупреждения о потенциальных нарушениях/ограничениях платформ без ложных обещаний «100% защита от бана». Монтаж и блюр также не устраняют авторские права.

## 7. Три режима анализа — цена / качество / приватность

### Lite (без нейросети, 100% бесплатный)
- FFmpeg/ffprobe, детектор смены сцен, VAD/анализ пауз, аудиоэнергии, темпа, движения/оптического потока, простая эвристика ранжирования;
- правила для чёрных кадров, титров, повторяющихся интро, длинных неречевых участков;
- экспорт и ручной таймлайн, контроль кадра по ключевым кадрам;
- **честное ограничение:** без семантического понимания сюжета Lite не способен стабильно определять смысловую «вирусность», наготу/насилие или сложные эмоциональные сцены. Не имитировать AI.

### Local AI (бесплатный, приоритетный)
- faster-whisper или аналог для речи, лёгкие модели детекции лиц/объектов, локальная модель для оценки выбранных кадров/коротких клипов и транскрипта;
- модели подбирать после аппаратного замера: RTX 4070 Laptop 8 GB VRAM, RAM 16 GB, Windows; квантование, ограничение контекста, динамический offload CPU и последовательный запуск моделей;
- базовая цензура и смысловое ранжирование по комбинации ASR + ключевых кадров + сцен, а не «просмотр» всего фильма одной моделью;
- один раз скачать модели, сохранять локально; показывать вес, лицензию и необходимость загрузки.

### Cloud / Hybrid Pro (необязательный, с контролем стоимости)
- отдельный абстрактный API-адаптер для внешнего мультимодального сервиса и сменяемых провайдеров (например, подходящие бюджетные модели с поддержкой текста/изображений/видео, если доступны);
- **не отправлять целый фильм по умолчанию**: локально построить транскрипт и shortlist сцен, затем по согласованию отправлять только небольшие кадры/фрагменты/описания;
- опциональное использование своего API-ключа (BYOK), стоимость до запроса (оценка), бюджет на проект, лимит запросов, кэш, retries/backoff, fallback на Local AI;
- никакой обязательной подписки, никакого скрытого облачного трафика, не хранить ключи в репозитории/логах; предупреждение о правах на загрузку контента во внешние сервисы;
- позже провести документированный сравнительный benchmark цены/качества на одинаковом наборе законных тестовых материалов, не выбирать API только по маркетингу.

## 8. Интерфейс полноценной Windows-программы

- Главный экран: импорт файла/папки, просмотр информации о медиа, выбор профиля YouTube-канала и режима обработки.
- **«Анализ серии»** — крупная основная кнопка; ручной выбор стартового таймкода не обязателен.
- Шкала сюжета с главами, важными сценами, исключениями, цензурой и монтажными решениями.
- Список кандидатов с визуальным превью, реальными source timestamps, длительностью, условным баллом по критериям и **человеческим объяснением «почему выбрано / почему не выбрано»**.
- Редактор планов: включить/исключить/переставить в допустимых режимах, настроить обрезку, аудио и цензуру.
- Предпросмотр **до финального рендера**: кроп 9:16, положение лиц, субтитры, эффекты и маски.
- Очередь задач: стадии, процент/ETA только если измерен, пауза/отмена/продолжение, журнал ошибок.
- Профили каналов: Serial, Viral/Music Edit, настройки длительности/языка, шаблоны, субтитры, стиль цензуры.
- Экспорт: именованные папки по проекту/серии/каналу, MP4, SRT, JSON/CSV таймлайна, таблица решений, предложенные названия/описания. **Публикация только после разрешения человека**.

## 9. Надёжность и высокая производительность

- Локальное Windows-приложение с неблокирующим UI; рассматривайте **PySide6** как вариант перехода от текущего Tkinter, но не переписывайте всё без оценки трудозатрат.
- Видеофайлы могут весить **многие ГБ**: stream/seek через FFmpeg, низкоразрешённые proxy-файлы для анализа, не загружать все видеокадры в RAM/GPU.
- Каждая стадия имеет кэш и checkpoint: probe → proxies → scene detection → transcript → ranking → edit decision list → reframe → censor → preview → render → QC.
- Избегать одновременного запуска всех тяжёлых AI-моделей на 8 GB VRAM. Показывать RAM/VRAM/диск и предупреждения об их нехватке.
- При доступности аппаратное NVENC-кодирование с проверкой качества, а также CPU fallback.
- Временные .partial результаты + атомарное завершение; оригинал никогда не перезаписывать.
- Возобновление после сбоя без пересчёта успешно завершённых этапов, идемпотентность, контролируемая отмена, безопасная очистка кэша.
- Никаких обязательных интернет-соединений в Lite/Local; офлайн-работа после загрузки моделей.
- Тесты для таймкодов, синхронизации, порезки/склейки, словарей, безопасности файлов; end-to-end smoke test на коротком клипе; реальные длительные прогоны на локальной машине.
- Видео, веса моделей, кэш и API-ключи исключить из Git через .gitignore; **не публиковать референсные/исходные фильмы в GitHub**.

## 10. Техническая реализация: предложенная модульная цепочка

`Import/Probe → Proxy/Scene Segmentation → Speech/VAD/ASR → Plot & Highlight Candidate Ranking → EDL/Storyboard → Smart Reframe → Subtitle/Music → Smart Censor → Preview/QC → Export`

- Разделить **analysis** (извлечение признаков), **decision** (решение что оставить/почему), **render** (техническая сборка).
- Хранить монтаж как редактируемый **EDL** (список сегментов с in/out исходника, кропом, масками, скоростью, звуком, субтитрами). Не «вшивать» алгоритмические решения в единственную необратимую FFmpeg-команду.
- Алгоритмы и модели должны быть заменяемыми; использовать явный контракт JSON / Python dataclasses и версионирование результатов.
- Объяснимый scoring (эвристический, сравнительный; **не выдавать score за доказанную вероятность вирусности**).

## 12. Критерии приемки (Definition of Done)

- [ ] Пользователь загружает серию и нажимает **«Анализировать» без ручного задания секунд**.
- [ ] Система предлагает конкретные сцены с **исходными таймкодами, кратким объяснением отбора и исключений**.
- [ ] В результате **нет случайных чёрных полос**; в обычных диалоговых сценах основное лицо находится в вертикальном кадре, а смена фокуса выглядит плавной.
- [ ] Заставка и финальные титры не попадают в автоматически предложенные ролики без особой причины; спорные случаи можно исправить.
- [ ] В быстром монтаже сокращены ненужные паузы **без обрыва речи, щелчков и смены смысла**.
- [ ] В Serial Cutter есть связные последовательные части; в Viral Moments — самостоятельные динамичные кандидаты.
- [ ] Работают субтитры, предпросмотр, объяснения, редактирование решений и экспорт.
- [ ] Smart Censor позволяет точечно размыть/заглушить и проверить все сомнительные случаи; нет ложного обещания платформенной безопасности.
- [ ] На доступном тестовом исходнике большого размера (>5 GB, если есть на тестовом компьютере) приложение не пытается загрузить весь файл в RAM, интерфейс остаётся отзывчивым; после принудительного прерывания работа возобновляется с последней завершённой стадии.
- [ ] Lite работает без скачивания AI-моделей, Local AI — без платных API, Cloud — только после явного включения и установки бюджета.
- [ ] Все ключевые функции имеют демонстрационные тесты и зафиксированные ограничения. Не маркировать заглушки или мок-результаты как реализованный AI.

## 13. Правила для Codex

1. Это **масштабный запрос на переработку продукта**, а не просьба изменить пару кнопок. Создай отдельные подзадачи/PR по этапам, но сохрани единую архитектуру.
2. Начни с реального аудита репозитория, не предполагай, что описанное уже существует.
3. Не обманывай пользователя фразами «готово» при наличии только интерфейса без работающего backend.
4. После каждого этапа: что реально работает → какие тесты запущены → как проверить на ПК → известные ограничения.
5. Сначала офлайн и бесплатный базовый функционал; дорогие модели/API только опционально, без израсходования бюджета без разрешения.
6. Референсные видео анализировать локально и не выгружать в репозиторий/внешние API автоматически.
7. Исходные фильмы/сериалы и сторонняя музыка должны использоваться с необходимыми правами; авторская переработка и цензура сами по себе не отменяют авторских прав.
8. Вопросы к пользователю задавать только если блокируют следующий этап; в остальном делать обоснованные инженерные предположения, фиксировать их в документации.

**Ожидаемый следующий ответ Codex:** технический аудит текущей версии, архитектура и проверяемый план P0–P2; затем начать реализацию P0, не ожидая дополнительных ручных команд на каждый файл.
