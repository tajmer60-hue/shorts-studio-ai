# Авторизация и обработка данных

## Текущая версия

Приложение однопользовательское и локальное. Регистрация, вход, сервер и HTTP API отсутствуют. Пароли, OAuth access/refresh tokens, JWT, API keys и секреты приложения не создаются и не запрашиваются. Подключение GitHub в Codex даёт среде разработки доступ к коду; его учётные данные не читаются и не используются приложением. Локальным пользователям Windows с доступом к файлам доступны и эти данные: отдельного шифрования приложение не выполняет.

## Компоненты и поток

1. `app.py:main()` выбирает локальную папку данных Windows (AppLocalDataLocation) либо `SHORTS_STUDIO_DATA_DIR`. Эта переменная — путь, не секрет. `QLockFile` предотвращает одновременную работу двух обычных экземпляров приложения в одной папке.
2. `Studio.add_job()` собирает существующий локальный исходник, таймкоды и новое имя результата. `JobStore.add()` записывает параметры в SQLite.
3. `Studio.poll()` берёт очередное задание, отмечает его running и запускает фоновый `export_worker()`; код GUI остаётся в главном потоке.
4. `render.probe()` вызывает локальный FFprobe и проверяет видеодорожку/длительность. `build_command()` проверяет диапазон, режим и защиту исходника.
5. FFmpeg получает список аргументов без shell и читает только разрешённые протоколы file/pipe. Дорожка звука необязательна. Рабочий процесс пишет уникальный временный MP4 рядом с результатом. `-n` запрещает перезапись временного файла.
6. После успешного завершения FFprobe проверяет временный MP4, затем он переименовывается в выбранный результат. Существующее имя результата не заменяется на Windows. Финальное событие обновляет SQLite и интерфейс.
7. При штатной отмене/ошибке удаляются только созданные этим заданием временные MP4/журнал. После аварийного завершения задания running становятся interrupted и требуют явного повтора; возможны оставшиеся временные файлы. Возобновление кодирования с середины пока отсутствует.

## Что хранится

SQLite хранит абсолютные пути исходников и результатов, таймкоды, режим, даты и сообщения о состоянии/ошибках. Эти сведения могут быть личными. Файл базы остаётся локальным и исключён из Git. Краткий журнал FFmpeg временный; часть ошибки может попасть в локальную SQLite. Отчёт анализа референса содержит имя файла, агрегированные измерения и ручные наблюдения. В Git следует отправлять только осознанно выбранные отчёты, без путей и транскриптов пользователя.

Секреты не хранятся в исходниках или настройках. Если будут добавлены сетевые сервисы, потребуются отдельный проект авторизации, явное согласие на передачу медиа и хранение секретов в системном хранилище Windows. Текущий код этих функций не содержит.
